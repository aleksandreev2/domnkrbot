# NekromantLib reader comments parity design

## Goal

Reproduce the lower reader surface from the user-provided `03 — Тайтлы и главы.zip` one-for-one in structure and interaction while keeping all social content native to NekromantLib. Do not copy RanobeLib comments, users, vote counts or translator identities.

## Reference surface

The saved normal reader state places the following blocks directly below the chapter text:

1. `Над главой работали` translation-credit block.
2. Primary `Поддержать` action.
3. Comment header with `Новые`, `Настройки`, `Правила`.
4. Comment composer with `Написать комментарий...`.
5. Comment thread rows with author identity, timestamp, body, score controls, reply, report and overflow controls.

Measured reference layout relevant to this slice:
- worker row max width: 930px; padding: `10px 16px`;
- comments surface background: reader `foreground`;
- comments inner max width: 930px; padding: `16px`;
- composer: `12px 0`; placeholder surface: `12px`, 4px radius, 1px `border-base`;
- comment body vertical padding: 10px;
- comment head desktop grid: `24px auto auto auto` with 10px column gap;
- comment content top margin: 10px and line-height 1.6.

The already verified reader top bar, text geometry, chapter list and settings remain unchanged.

## Native data model

Use the existing `users.telegram_id TEXT` identity model and Telegram web-session auth. No parallel integer user model is introduced.

### `reader_chapter_comments`

- `id TEXT PRIMARY KEY` (UUID generated by the Worker)
- `book_ref TEXT NOT NULL`
- `chapter_id INTEGER NOT NULL`
- `author_telegram_id TEXT NOT NULL`
- `parent_comment_id TEXT NULL`
- `body TEXT NOT NULL`
- `created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP`
- `updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP`
- `deleted_at TEXT NULL`
- FK `author_telegram_id -> users(telegram_id) ON DELETE CASCADE`
- FK `parent_comment_id -> reader_chapter_comments(id) ON DELETE CASCADE`

Indexes:
- `(book_ref, chapter_id, created_at DESC, id DESC)`
- `(parent_comment_id, created_at ASC, id ASC)`
- `(author_telegram_id, created_at DESC)`

Replies persist one direct parent. The API rejects a parent comment from another title/chapter. Rendering can indent the reply tree without importing RanobeLib conversation state.

### `reader_chapter_comment_votes`

- `comment_id TEXT NOT NULL`
- `voter_telegram_id TEXT NOT NULL`
- `value INTEGER NOT NULL CHECK(value IN (-1, 1))`
- `created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP`
- `updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP`
- primary key `(comment_id, voter_telegram_id)`
- FK `comment_id -> reader_chapter_comments(id) ON DELETE CASCADE`
- FK `voter_telegram_id -> users(telegram_id) ON DELETE CASCADE`

Displayed score is `SUM(value)` from native votes. Zero is real zero, never copied reference data.

## API

Create a focused `src/web-reader-comments.ts` handler using the same helpers as collection comments: `getSessionUser`, `isSameOriginMutation`, `isAdminUser`, and an upsert into `users`.

- `GET /api/reader/comments?ref=<book_ref>&chapter=<chapter_id>`
  - public read;
  - validates ref/chapter;
  - returns comments for only that chapter, native score, `myVote`, `isOwn`, `canDelete`;
  - `canDelete` is true for the comment author or a configured admin.
- `POST /api/reader/comments`
  - authenticated + same-origin;
  - JSON: `bookRef`, `chapterId`, `body`, optional `parentCommentId`;
  - validates the synchronized title/chapter exists;
  - trims body and limits it to 3000 characters;
  - upserts Telegram user and inserts UUID comment.
- `DELETE /api/reader/comments/:id`
  - authenticated + same-origin;
  - author or configured admin only;
  - soft-deletes (`body=''`, `deleted_at=CURRENT_TIMESTAMP`) to preserve reply topology.
- `PUT /api/reader/comments/:id/vote`
  - authenticated + same-origin;
  - JSON value `-1`, `0`, or `1`;
  - `0` deletes the current viewer vote, ±1 upserts it;
  - deleted comments cannot receive votes.

Route the focused handler in `src/live-entry-v2.ts` before falling through to the legacy/base Worker. The existing `/api/title` and `/api/reader/chapter` route ownership remains unchanged in `src/live-entry.ts`.

The report control remains present in the captured position but disabled until a real moderation/report contract exists.

## UI parity

Add directly below the chapter text while preserving the current reader text column above it:

- worker row matching the saved max-width/padding and showing only the real `Дом Некроманта` team identity/logo;
- `Поддержать` primary action. Use the project’s real Boosty team destination (`https://boosty.to/domnekromanta`), not a fabricated donation flow;
- comments section on reader foreground background with a 930px inner container;
- captured header order: `Новые`, disabled `Настройки`, `Правила`;
- composer surface displaying `Написать комментарий...` when collapsed;
- signed-out interaction mounts Telegram login instead of silently failing;
- signed-in interaction expands a textarea and posts without reload;
- comment rows mirror saved desktop hierarchy: 24px avatar, author, timestamp, body, reply/report/overflow controls and right-side up/down score control;
- `жалоба` stays disabled until reports exist;
- delete is exposed only when API returns `canDelete=true`;
- reply composer is inline beneath the selected comment;
- long native comments can use `Показать полностью` collapse behavior without importing any reference text.

No RanobeLib usernames, comment text, reactions, streaks, pinned comments or counts are seeded.

## Session and errors

- Reader boot also fetches `/api/auth/session` so composer behavior matches the authenticated state.
- Failed comments read shows a compact retry/error state without hiding the chapter text.
- Failed post/vote/delete preserves typed content where relevant and shows an inline message.
- Deleted parent comments render a neutral `Комментарий удалён` marker so replies remain attached.

## Non-goals

- importing RanobeLib comments/accounts/streaks/pinned content;
- report moderation in this slice;
- copying RanobeLib application source or branded assets;
- scanner, translation lifecycle or Telegram notification changes;
- changing the already verified reader header/settings/chapter-list parity.
